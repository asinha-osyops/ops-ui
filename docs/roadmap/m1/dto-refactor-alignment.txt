API Client OpenAPI Migration Plan

 Overview

 Update the API client (lib/api-client.ts) to match the new OpenAPI specification in openapi.json. This involves updating 1,243 lines of API client code and 20 consuming files across pages and
 components.

 Implementation Approach: Single comprehensive PR with all changes (user confirmed)
 Backend Status: Already updated and ready (user confirmed)
 CIO Role: No existing usage, safe to remove (user confirmed)
 Backward Compatibility: Single breaking change, no compatibility layer needed (user confirmed)

 Key Changes Required

 1. RoleTitle Enum - BREAKING CHANGE (HIGH IMPACT)

 - Current: 36 role values (CEO, CFO, COO, CTO, CIO, CMO, DIRECTOR, MANAGER, etc.)
 - New: 60+ role values including hierarchical structure and medical roles
 - Breaking Changes:
   - CIO removed (needs migration to CTO or CPO)
   - Generic roles renamed (e.g., DIRECTOR → ENGINEERING_DIRECTOR)
   - New medical roles added (DENTIST, PHYSICIAN, NURSE_PRACTITIONER, etc.)
 - Affected Files: 4 files directly reference RoleTitle values

 2. Request DTO Pattern Changes (HIGH IMPACT)

 - Current: Pass objects directly or wrapped (e.g., { sop: sopData })
 - New: Use specific Request DTOs (CreateSopRequestDto, UpdateSopRequestDto, etc.)
 - Impact: All create/update methods need DTO wrappers removed

 3. File Upload Structure Changes (MEDIUM IMPACT)

 - Current: FormData with separate fields (file, companyId, sopId)
 - New: FormData with requestDto (JSON) + file
 - Affected Files: 2 files (SOP create, Log create)

 4. Batch → Bulk Renaming (MEDIUM IMPACT)

 - Type Names: BatchCreateEmployeesRequestDto → BulkCreateEmployeesRequestDto
 - Endpoint URLs: /employee/batch → /employee/bulk
 - Method Names: Already correct (bulkCreateEmployees)
 - Affected Files: 3 files (Employee components)

 5. Response Type Changes (MEDIUM IMPACT)

 - Current: Many return { success, message } wrapper objects
 - New: Return entities directly or void
 - Impact: Error handling changes from checking response.success to try/catch

 6. New Update Endpoints (LOW-MEDIUM IMPACT)

 - Add PUT /api/sop/{id} - Update SOP
 - Add PUT /api/log/{id} - Update Log
 - Verify existing Company, Employee, Role, ActivityEvent update endpoints

 7. StepDto Changes (LOW IMPACT)

 - Remove actorRoleId field (likely unused, nullable)
 - Keep actorRoleTitle field only

 Breaking Changes Summary

 1. RoleTitle Enum: Complete replacement, CIO removed (no existing usage), 24+ new values
 2. Response Types: Direct entity returns instead of { success, message } wrappers
 3. Request Unwrapping: No more { sop: sopData } wrapper objects
 4. File Upload Structure: requestDto field instead of separate parameters
 5. Endpoint URLs: /employee/batch → /employee/bulk

 Note: All breaking changes deploy atomically in single PR - no migration period needed.
